## 做了什么
中本聪在 `uint256.h` 实现了两个自定义的超大正整数类型，分别是 `uint256` 和 `uint160`。并分别为这个两个超大整数类型实现了基础运算符：
- 位运算符: ~, ^, &, |, <<, >>
- 算术运算符: +, -, ++, --
- 比较运算符: <, <=, >, >=,!=
- 转换方法: GetHex(), SetHex(), ToString()
- 序列化方法: Serialize(), Unserialize()

定义的新类型的原理非常简朴，就是 " 大的放不下，就拆分成几个小的放 "。比如需要一个正整数，它有 256 位 (换成二进制需要 256 个 bit 才能存下)，那么就将这个超大的整数分成 8 个区间，每个区间大小相同都是 32 位。
```c++
template <unsigned int BITS> class base_uint {

protected:
enum { WIDTH = BITS / 32 }; // 计算需要多少个32位整数来存储BITS位的大整数
unsigned int pn[WIDTH]; // 用数组存储大整数的各个部分，每个元素32位
// ...
}
```
这里首先定义的是一个更基础的类型 `base_uint`，然后通过这个基础类型去定义 `base_uint<160>` 和 `base_uint<256>`，即最终的类型 `uint160` 和 `uint256`。因为这两个类型来自同一个基础类型，所以需要的运算符应该一模一样，但中本聪在这里重复实现了两次，它为 `uint160` 和 `uint256` 实现了完全相同的。从代码工程上看，这部分的确是冗余的。中本聪老哥也是耿直人，还特意在代码中留下注释：
```text
// uint160 and uint256 could be implemented as templates, but to keep
// compile errors and debugging cleaner, they're copy and pasted.
// It's safe to search and replace 160 with 256 and vice versa.

// uint160和uint256可以用模板实现，但为了保持编译错误和调试更清晰，它们是复制粘贴的
// 可以安全地搜索替换160和256
```

## 为什么要定义这两个数据
定义新的数据类型是为了用。哈希值是比特币中最常用的数据：
- 区块需要 sha256 哈希值来标识、
- 交易需要 sha256 哈希值来标识、
- Merkle 数的构建也需要 sha 256，
- 工作量证明需要找到特定的 sha 256 哈希值进行比较

这些都离不开 sha256。SHA-256（Secure Hash Algorithm 256-bit）是一种加密哈希函数，无论输入数据多长，输出始终是 256 位（32 字节）。固定函数输出长度在密码学中非常重要，它意味着可以防止长度扩展攻击以及便于硬件优化。

然而 C++ 的标准数据类型中是不包含这么大的数据的。
```
// 标准C++整数类型：
char           : 8位
short          : 16位
int            : 32位
long           : 32或64位（取决于平台）
long long      : 64位

// 没有超过64位的整数类型！
```
因此才需要自己定义一个新的类型，用于存储 sha256 的哈希值。

至于 sha160 则是为了 " 地址 " 而量身定制，因为在比特币中用到固定长度为 20 字节 (160 bit) 的数据有且只有一个，就是 " 比特币地址 "(这里涉及到地址生成方式和 Ripemd160 的使用)。

## 为什么没有析构函数
中本聪在代码注释中写道：
```
“// We have to keep a separate base class without constructors // so the compiler will let us use it in a union”
```
这是因为 C++ 联合（`union`）的核心语法限制导致的。在 `union` 联合体内部，不能直接存放带有自定义构造 / 析构函数的非平凡类型对象。所以这里定义的新类型才没有析构函数，只是为了满足 union 的语法要求，让编译器放行。

## 运算符重载
既然是自定义的一个新的数据类型，那么自然少不了对与此类型的运算。几乎是把整数需要的操作符都搬了过来，函数风格都是同一个模版。
```c++
const base_uint operator~() const // 按位取反运算符
{
  base_uint ret;
  for (int i = 0; i < WIDTH; i++)
    ret.pn[i] = ~pn[i];
  return ret;
}
```
如上面这个方法，`operator~()` 是对 C++ 按位取反运算符 `~` 的重载，`const` 修饰符表示该函数不会修改调用对象的状态。方法内部遍历原对象的所有 32 位部分，依次取反，最近返回新对象。
重载运算符的确对代码可读性提升很大，使用 `~a` 比 `a.bitwise_not()` 的确更直观。
