## 什么是编码，为什么要编码
编码（Encoding) 就是将原始信息按照规则转换为另一种格式，而解码 (Decoding) 就是将编码后的格式逆向还原，恢复出原始信息。

不同的 Agent 擅长处理的 ' 语言 ' 不一样，编码有点像‘语言翻译’，将目标语言翻译成 Agent 能听得懂的语言。比如 UTF-8 编码就是将人类可读的字符串，翻译成机器可读的二进制。base64 就是将机器可读的二进制，翻译成人类可读的字符串。

## Base58.H 的目的
这部分代码的核心目的是 " 地址生成与检测 "。因为 " 比特币地址 " 其实是给人用，机器要的不是地址，而是 " 公钥 "。因此代码设计中，必须存在一个“编码”的行为，将某种 " 二进制 " 信息，翻译成人类可以阅读使用的 " 字符串 "，这也是 base58 在比特币中存在的意义。

源代码的结构是简单清晰的，200 多行大部分都在做函数重载，核心函数如下：
1. 编码
2. 解码
3. 解码检测
4. 地址生成
5. 地址检测

## 为什么采用 Base58 而不是 Base64
中本聪在代码注释中给出了清晰的解释。

> //
> // Why base-58 instead of standard base-64 encoding?
> // - Don't want 0OIl characters that look the same in some fonts and
> // could be used to create visually identical looking account numbers.
> // - A string with non-alphanumeric characters is not as easily accepted as an
> // account number.
> // - E-mail usually won't line-break if there's no punctuation to break at.
> // - Doubleclicking selects the whole number as one word if it's all
> // alphanumeric.
> //

 - 不希望出现某些字体中看起来相同的“0OIl”字符，因为这些字符可能会被用来生成看起来完全相同的账号号码。
- 包含非字母数字字符的字符串不如账号号码那样容易被接受。
- 如果电子邮件中没有标点符号来分隔，它通常不会换行。
- 如果全是字母数字字符，双击操作会将整个数字视为一个单词进行选择。

可见，这部分主要考虑的是人机交互问题。

## 从公钥如何到地址
base58 只是工具，地址生成与检测才是核心。函数 `PubKeyToAddress`、`Hash160ToAddress`、`Hash160` 三个函数共同描述了地址生成的完整过程，基本流程如下：
```PlainText
私钥（32字节）
    ↓ 椭圆曲线运算
公钥（33或65字节）
    ↓ SHA-256
SHA-256哈希（32字节）
    ↓ RIPEMD-160
RIPEMD-160哈希（20字节）
    ↓ 添加版本号
[版本][20字节哈希]（21字节）
    ↓ 计算校验和
SHA-256(SHA-256([版本][哈希])) → 前4字节
    ↓ 组合数据
[版本][20字节哈希][4字节校验]（25字节）
    ↓ Base58编码
比特币地址字符串（27-34字符）
```

```
公钥 → SHA-256 → RIPEMD-160 → Base58Check编码 → 地址
```
通过椭圆曲线生成的密钥对中的公钥，经过 `sha-256` 和 `RIPEMD-160` 两次哈希后，得到一个 20 字节的负载数据，然后负载的基础上，前缀加上版本号 (1 字节),。将加上前缀的数据 (21 字节) 经过 SHA-256 后得到一个新哈希，并取前面 4 个字节作为后缀，添加到版本号 + 负载后面，生成一个原始地址（25 字节）。这里特别像身份证，前缀是省份编号，中部是生日信息，后缀是校验码。
```
[1字节版本][20字节哈希][4字节校验]
```
再通过 base58 编码后，生成一个字符串，这个字符串就是最终人类可阅读的 " 比特币地址 " 了。
```
[1字节版本][20字节哈希][4字节校验] -> BASE58编码
```

```c++
// base58.h
/**

* @brief 将公钥转换为比特币地址

* @param vchPubKey 公钥的字节数据

* @return 编码后的比特币地址字符串

*

* 过程：公钥 → SHA-256 → RIPEMD-160 → Base58Check编码 → 地址

*/

inline string PubKeyToAddress(const vector<unsigned char> &vchPubKey) {

return Hash160ToAddress(Hash160(vchPubKey));

}
```

```c++
// base58.h

* @brief 将160位哈希转换为比特币地址（Base58Check编码）

* @return 编码后的比特币地址字符串

*

* 地址格式：[1字节版本][20字节哈希][4字节校验] → Base58编码

* 版本号0表示主网普通地址

// add 1-byte version number to the front

return EncodeBase58Check(vch);

}
```

## 公钥是怎么来的
公钥来自于椭圆曲线的密钥对，在其他源代码分析中有详细分析，这里不再赘述。

## 公钥为什么要经过两层哈希了
```c++
// uitl.h
inline uint160 Hash160(const vector<unsigned char>& vch)

{

uint256 hash1;

SHA256(&vch[0], vch.size(), (unsigned char*)&hash1);//第一次使用sha256进行哈希运算

uint160 hash2;

RIPEMD160((unsigned char*)&hash1, sizeof(hash1), (unsigned char*)&hash2);//第二次进行ripemd160进行哈希运算

return hash2;

}
```
从源码上看，公钥不仅需要经过两层哈希，而且两次哈希的算法都不一样。中本聪并未在代码中给这个做法的具体解释，我们只能反向推测这样做的真实理由。
第一，如果这部分的真实目的是为了生成 " 比特币地址 "，而地址是给人阅读的，因此必须考虑人在使用地址中方便和安全。

第二，机器的语言是二进制语言的，但人类自然不会去读取二进制流，所以这里必须编码，将二进制翻译成字符串。基于防止字符误读的需求，中本聪选择了 base58 作为编码器。

第三，地址的长度是需要统一固定的，这符合人类工程学。因此编码的输入就必须是固定的，那么选择怎样的长度就是必须深思熟虑了，中本聪选择了 20 字节作为编码的输入长度，大概率是基于编码效率和可阅读性。

第四, `RIPEMD160` 可以输出长度为 20 字节的二进制流，简单、快速，但是它可能不大安全，有被碰撞的风险。

第五，`SHA256` 也可以输出固定长度的二进制流，但是它的输出还是有点太长了 (32 字节)。

第六，基于阅读性和安全性的综合考量，选择了双重哈希方案，先经过 `SHA256` 然后继续 `RIPEMD160`，这样既能更好的保障安全 (防止哈希碰撞)，也能输出较为合理的地址长度。

## 安全性在哪里
上述的推理有个重大的漏洞，因为前提是假设哈希碰撞成功，公钥到地址的过程被逆转。但是实际上，在比特币系统中，公钥本来就是全部公开的，即便公钥到地址的过程被逆转，也似乎没有什么安全性的问题。

事情当然没有这么简单。公钥暴露本身不是问题，真正的风险是地址碰撞导致的资金损失和钓鱼攻击。假设这里的哈希过程被破解，那么击者可以生成公钥 2，使得生成的地址与受害者的地址相同。如果恰好攻击者也拥有公钥匙 2 对应的私钥，那么攻击者可以花掉这笔他的钱。而受害者在钓鱼网站中，以为转入的资金是到自己的地址，其实是攻击者的地址。

因此这里的哈希过程，实际上保护的不是公钥不泄漏，而是保障地址的唯一性。

## 地址的校验
如何判断一个地址是否合法，就是把地址解码后，然后把 " 生成地址 " 的过程再走一遍，然后检测这其中的任何一步是否有错误。
```c++

inline bool AddressToHash160(const char *psz, uint160 &hash160Ret) {
  vector<unsigned char> vch;
  if (!DecodeBase58Check(psz, vch))
    return false;
  if (vch.empty())
    return false;
  unsigned char nVersion = vch[0];
  // 检查长度：必须是1字节版本 + 20字节哈希 = 21字节
  if (vch.size() != sizeof(hash160Ret) + 1)
    return false;
  memcpy(&hash160Ret, &vch[1], sizeof(hash160Ret));
  // 验证版本号：只接受主网地址版本
  return (nVersion <= ADDRESSVERSION);
}
```
```PlainText

比特币地址字符串
    ↓ Base58解码
字节数组（25字节）
    ↓ 分离组件
[版本][20字节哈希][4字节校验]
    ↓ 验证校验码
重新计算SHA-256(SHA-256([版本][哈希]))
比较前4字节与校验码
    ↓ 验证版本号
检查版本号是否有效
    ↓ 验证长度
检查总长度是否为25字节
    ↓ 提取哈希
得到20字节的公钥哈希
```
